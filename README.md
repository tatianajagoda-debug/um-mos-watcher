# um-mos-watcher

Следит за страницей экскурсий [um.mos.ru/excursions/?isOpen=true](https://um.mos.ru/excursions/?isOpen=true) и присылает уведомление в Telegram, когда появляется новый слот с открытой записью.

Работает на GitHub Actions: бесплатно, в облаке, каждые 20 минут. Твой компьютер можно выключать — задача всё равно запустится.

## Что внутри

- `watch.py` — парсер сайта + отправка в Telegram
- `requirements.txt` — зависимости (requests, beautifulsoup4)
- `.github/workflows/check.yml` — расписание запусков
- `state.json` — список уже виденных слотов; обновляется автоматически

## Первая настройка

### 1. Получи свой `chat_id` в Telegram

1. Открой бота `@Um_Mos_Watcher_bot`, нажми **Start** (или просто напиши ему «привет»)
2. Открой в браузере (вставь токен в URL):
   ```
   https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates
   ```
3. В JSON найди `"chat":{"id": 123456789, ...}` — это число и есть `chat_id`

### 2. Создай приватный репозиторий

1. Зайди на [github.com/new](https://github.com/new)
2. Имя репозитория — например, `um-mos-watcher`
3. Сделай его **Private** (важно: токен бота будет в Secrets, но репо лучше всё равно приватный)
4. Создай без README/gitignore/license — все файлы у тебя уже есть локально

### 3. Загрузи файлы

В этой папке (`D:\Projects\um-mos-watcher`) выполни в терминале:

```bash
git init
git add .
git commit -m "initial: um.mos.ru watcher"
git branch -M main
git remote add origin https://github.com/<твой_логин>/um-mos-watcher.git
git push -u origin main
```

Если git не установлен — поставь [Git for Windows](https://git-scm.com/download/win) или загрузи файлы вручную через GitHub UI (кнопка **Add file → Upload files** на странице репо).

### 4. Добавь секреты

На странице репозитория: **Settings → Secrets and variables → Actions → New repository secret**

Создай два секрета:

| Имя                | Значение                                    |
|--------------------|---------------------------------------------|
| `TELEGRAM_TOKEN`   | токен от @BotFather                         |
| `TELEGRAM_CHAT_ID` | число из шага 1                             |

### 5. Запусти первый прогон вручную

Открой вкладку **Actions** → выбери workflow **Check um.mos.ru excursions** → нажми **Run workflow**.

Первый запуск **намеренно не пришлёт уведомлений** — он только запомнит, какие экскурсии уже есть на сайте. Со второго запуска (через 20 мин) ты будешь получать сообщения только о новых.

Дальше GitHub будет сам запускать задачу каждые 20 минут.

## Проверить, что всё работает

- В **Actions** видно историю запусков, можно открыть лог и убедиться, что слотов распознано ~250–280
- В `state.json` после каждого запуска обновляется поле `last_run`
- Если что-то ломается — лог покажет ошибку

## Изменить частоту проверки

Открой `.github/workflows/check.yml`, поменяй cron-выражение:

| Хочешь                | Cron                |
|-----------------------|---------------------|
| Каждые 20 мин (сейчас)| `*/20 * * * *`      |
| Каждые 15 мин         | `*/15 * * * *`      |
| Каждый час            | `0 * * * *`         |
| Каждый день в 9 утра МСК | `0 6 * * *`     |

**Важно:** GitHub Actions cron не гарантирует точную минуту — может запуститься с задержкой 5–15 минут под нагрузкой. Для отслеживания экскурсий это не критично, новости всё равно приходят почти сразу.

## Сколько это стоит

- Публичные репозитории — **бесплатно без ограничений**
- Приватные — **2000 бесплатных минут в месяц**. Наш запуск длится ~30 секунд, при 20-минутном интервале это ~36 минут в сутки, ~1100 минут в месяц. Влезает с запасом.

## Если что-то сломалось

Самые вероятные причины:
1. Сайт `um.mos.ru` поменял HTML-разметку. Открой Actions-лог, посмотри сколько слотов распознано — если 0, парсер надо чинить
2. Telegram забанил/удалил бота. Создай нового через @BotFather, обнови `TELEGRAM_TOKEN`
3. GitHub Actions переполнили лимит минут. Сделай репозиторий публичным или уменьши частоту

## Что считается «новым событием»

Уникальный ID слота = `<slug экскурсии>|<дата>|<время>`. Уведомление приходит когда:
- появилась новая экскурсия (новый slug)
- у существующей экскурсии открылась запись на новую дату/время
- слот, который раньше был закрыт, снова появился в списке `isOpen=true`
